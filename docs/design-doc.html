概要

ユーザーが楽譜PDFを開くと、OMR(光学楽譜認識)エンジンAudiverisが五線譜上の音符を認識し、その音符の上に固定ドのドレミ(カタカナ)を自動的にラベル表示する。再生機能(Web Audio APIによる音声合成)、ピアノロール表示、移調、速度変更、両手別ミュート、ドレミ付きPDFのダウンロードなどを備える。

設計の核になっているのは「OMRが検出した音符のピクセル座標をそのまま使い、元のPDF画像の上にラベルを重ねる」という方針である。座標を自力で再計算せず、Audiveris自身が解析に使った画像と完全に同じ座標系のデータを使うことで、ラベルのズレという最も起こりやすい失敗モードを構造的に防いでいる。

Electronの標準的な2プロセス構成。contextIsolation: true / nodeIntegration: false とし、renderer からは preload.ts が公開する window.musicSheet API を介してのみ main プロセスの機能(ファイルI/O・Audiveris起動)を呼び出す。renderer が直接 Node.js API に触れることはない。

03

主要な設計判断

3.1 座標の正本はAudiveris、音高の正本はMusicXML

ラベルの位置はomr-sheet.tsがAudiverisの内部グラフ(符頭 <head> の <bounds>)から直接取得する。描画を自前で行って座標を再計算する方式は、拡大縮小やウィンドウ幅の変化のたびにズレが蓄積するため採用していない。音高・リズムは同じMusicXMLをmusicxml-notes.tsで独立にパースし、インデックス順で両者を対応付ける。

3.2 グランドスタッフの2つの表現形に対応

ピアノ曲のMusicXMLは、Audiverisの出力によって(a) 1つの<part>内で<staff>タグにより両手を区別する形と、(b) 両手が完全に別々の<part>要素になる形のどちらでも出てくる。後者は<staff>タグを持たないため、partIndexを手の区別として代用する。

3.3 小節・段・ページの三重同期

2パート構成のとき、各パートは独立に時間カーソルを進めると、OMRの読み取り誤差(符点の誤認識や休符の欠落)が小節ごとにわずかに蓄積し、曲が進むにつれて片手がもう片手より早く(または遅く)なっていく。

対策として、全パートを小節インデックス単位でロックステップ処理し、各小節の終わりで「どちらかのパートが到達した最大時刻」に両方のカーソルを強制的に同期させる。これにより1小節分の誤差が次の小節に持ち越されない。

ラベルの並び順についても同様の注意が必要で、Audiverisの.omr内部データは「1つの段(システム)の中でパート1の全小節→パート2の全小節」という順序でまとまっている。これは単純な小節単位の交互配置とも、パート単位の一括配置とも異なるため、<print new-system> / <print new-page> を境界として段ごとにまとめ、段の中でパートごとにまとめて出力する。

3.4 ラベルの衝突回避

label-layout.tsは、音符の真上(または2声目は真下)を起点に、既存ラベルと矩形が重なる限り段(tier)を1つずつ外側へ押し出す単純な貪欲法。CanvasのmeasureTextで実際のラベル幅を計測してから配置するため、カタカナの文字数(「ド」〜「ファ#」など)が異なっても詰まりすぎない。

04

音声合成エンジン

外部のピアノ音源・サウンドフォント・サンプル素材は一切使用していない。audio-player.tsが Web Audio API の OscillatorNode + PeriodicWave だけで、音色ごとに倍音構成(ハーモニクス配列)とエンベロープ形状を変えて加算合成している。

データ永続化

変換結果はapp.getPath('userData')/score-cache/<SHA-256ハッシュ>/に保存される。同一PDFを再度開いた際はAudiverisを再実行せず、キャッシュから即座に読み込む。

06

既知の制約

OMR認識精度そのものには依存する。Audiverisが符頭を検出できなかった音は、アプリ側のどの処理段階でも復元できない。

Audiveris自身が低信頼度と判定した小節には .omr 内で abnormal="true" が付与される(実例: ある楽譜で全100小節中21箇所)。密な和音やト音記号⇔ヘ音記号の切り替えが多い箇所で発生しやすい。

単一テンポ前提。曲中の<sound tempo>変化は反映されず、最初に見つかったテンポ(無指定時120bpm)で全体の時間軸を計算する。

固定ドのみ。移動ド・オクターブ表記には対応しない(MVP範囲外として設計時に除外)。

OMR誤認識の手動修正UIは無い。AIによる低信頼度小節の再読み取り機能を試作したが、Anthropic API利用のための別課金が発生するため不採用とし撤去済み。
